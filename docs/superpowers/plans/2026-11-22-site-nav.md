# Site Navigation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:**
- One page header with an optional back link on every page.
- The deprecated color aliases removed.
- The right header item highlighted (saved builds → My builds).
- A way back from a Rack build and from a saved build.
- A "Builder · n of 5 / ready" count from the local draft.

**Architecture:**
- **Shared components:** `navItems.ts` gains two pure helpers, `activeNavItem` and `builderLabel`, that `SiteHeader` and `SiteFooter` render from. `PageHeader` gains `back`.
- **The count:** it comes from a builder-feature hook, `useDraftProgress`, which reads the draft's `localStorage` key via `useSyncExternalStore`. The route `Layout` passes it down as a prop, so shared components never import a feature.

**Tech Stack:** React 19, TypeScript, react-router, Tailwind v4, Vitest + Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-22-site-nav-design.md`

## Global Constraints

- **Branch:** `oa-site-nav`, which already contains #60 and #61. Never commit `skills-lock.json`, `.agents/skills/ui-taste/` or `.agents/skills/unslop/`.
- **Layers:** `src/components/shop` must not import `@features/*`. The count enters through props from `src/routes/AppRoutes.tsx`.
- **Copy, verbatim:**
  - "← Community Rack", "← My builds"
  - the pill text "<n> of 5" and "ready"
  - the accessible names "Builder, <n> of 5 picked" and "Builder, rig ready"
- **Page title classes:** `text-[28px] font-medium text-olive`.
- **Deprecated alias → token** (from the block in `src/styles/index.css`): `te-papa-green`→`olive`, `plantation`→`olive`, `spectra`→`belly`, `tasman`→`ink-2`, `sulu`→`belly`, `cod-gray`→`ink`, `linen`→`stone-page`, `bone`→`stone-raised`, `twine`→`ink-3`. Keep each utility's prefix and modifiers (`hover:bg-te-papa-green` → `hover:bg-olive`, `focus:ring-spectra/30` → `focus:ring-belly/30`). It's a pure swap: the colors don't change.
- **The draft key:** `'rpp:build:v2'`; the change event is `'rpp:draft-change'`.
- The React Compiler is on: no hand-written `useMemo`/`useCallback`.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **The draft is cleared on the summary (Start over, Save this rig).** The count must drop to none without a navigation, because `LocalBuildProvider` dispatches `rpp:draft-change` on every write, including `clearBuild`. Tested in Task 2.
2. **`localStorage` is unavailable** (Safari private mode throws). `useDraftProgress` must return 0, not crash the shell. Tested in Task 2.
3. **An old saved-build link** (`/builder/12/rod/all`) must highlight My builds, not Builder. The existing header test asserts Builder and must change. Tested in Task 1.
4. **A Rack build opened in a new tab from the list** has no `state.from`, so it must be a plain link to `/rack`, not `navigate(-1)` out of the site. Tested in Task 3.
5. **A Cmd-click on "← Community Rack"** must open the list in a new tab, not go back. Tested in Task 3.

### Task 2: `useDraftProgress`, wired through the route layout

**Files:**
- Create: `src/features/builder/hooks/useDraftProgress.ts`
- Modify: `src/features/builder/hooks/LocalBuildProvider.tsx` (dispatch the event in `writeStorage` for the draft key), `src/features/builder/index.ts` (export the hook), `src/routes/AppRoutes.tsx` (`Layout` passes `builderProgress`)
- Test: `src/features/builder/hooks/useDraftProgress.test.tsx`

**Interfaces:**
- Produces: `useDraftProgress(): { picked: number }`. It counts the keys among `rod, reel, line, leader, tippet` whose value is a non-empty string in `JSON.parse(localStorage['rpp:build:v2'])`. Any throw (bad JSON, no storage) → 0.
- Consumes: `SiteHeader` and `SiteFooter`'s `builderProgress` (Task 1).

- [ ] **Step 1: Write the failing tests.** Render a harness that prints `picked`.
  - `it('is 0 with no draft and with a malformed one')`
  - `it('counts only the five parts')`: a stored `{ rod: 'rod-1', reel: 'reel-2', junk: 'x', line: 5 }` → 2.
  - `it('updates when the draft changes in this tab')`: set storage, `act(() => dispatchEvent(new Event('rpp:draft-change')))` → the new count.
  - `it('updates when another tab changes the draft')`: a `StorageEvent('storage', { key: 'rpp:build:v2' })`.
  - `it('is 0 when storage throws')`: `vi.spyOn(Storage.prototype, 'getItem').mockImplementation(() => { throw new Error('denied') })`.
  - **`LocalBuildProvider`:** `it('announces every draft write')`. Render the provider with a child calling `selectPart`, spy on `window.dispatchEvent`, and expect an `rpp:draft-change` event. Also call `clearBuild` and expect another.
- [ ] **Step 2: Run the tests and confirm they fail.** Run `pnpm vitest run src/features/builder/hooks`. Expected: FAIL.
- [ ] **Step 3: Implement.**
  - **The hook:** `useSyncExternalStore(subscribe, getSnapshot, () => 0)`. `subscribe` adds `storage` and `rpp:draft-change` listeners; `getSnapshot` returns the count, a number, so the snapshot is stable.
  - **`LocalBuildProvider`:** dispatch `new Event('rpp:draft-change')` after writing `STORAGE_KEY`.
  - **`Layout`:** `const { picked } = useDraftProgress()`, passed to both `SiteHeader` and `SiteFooter`.
- [ ] **Step 4: Run the full suite.** Run `pnpm test`. Expected: all pass, including the route tests that render `AppRoutes`.
- [ ] **Step 5: Commit.** `git commit -m "Count the draft's parts for the header from every page"`
